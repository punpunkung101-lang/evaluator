# คำถามเฉพาะระบบ (Specific Indicators) — ระบบที่เหลือ 20 ระบบ

> เสริมจาก `project_brief_evaluation_platform.md` §13 (ซึ่งเป็นชุดตัวอย่างของ `SYS018` ระบบซ่อมและบำรุงรักษา)
> วางที่ `docs/system_specific_questions.md` แล้วให้ Agent รวมเข้า `database/question-bank.json`

## หลักการใช้ร่วมกัน

- ทุกระบบใช้ **Core Indicators** (U, E, EF, D, R, S) ตาม brief เหมือนกัน
- หมวด **T (Tracking & Transparency)** แสดงเฉพาะระบบที่ `has_tracking = ใช่` (มีสถานะ/ขั้นตอนให้ติดตาม)
- Specific ของแต่ละระบบ: **บทบาท 2–3 กลุ่ม**, **flow สั้น 3–4 ขั้น**, **คำถามเฉพาะ 3–4 ข้อ** (ไม่ต้องมี Path A/B/C หรือ 8 สถานะแบบ SYS018)
- ชนิดคำตอบ: `R` = Rating 1–5 (+N/A), `Y` = ใช่/ไม่ใช่, `C` = เลือกหลายข้อ, `S` = เลือกข้อเดียว, `N` = ตัวเลข, `L` = ข้อความยาว
- ทุกข้อ Admin แก้/ปิดได้ ไม่ hard-code ข้อความด้านล่างเป็นค่าตายตัวในโค้ด
- บทบาท "ผู้ใช้ทั่วไป" = บุคลากร/อาจารย์/นักศึกษาที่ใช้ระบบ "เจ้าหน้าที่/ผู้ดูแล" = ผู้บริหารจัดการข้อมูลในระบบ

## กลุ่มข้อมูลบุคลากรและงานทรัพยากรบุคคล

### SYS001 รายชื่อบุคลากร  · has_tracking: ไม่
- บทบาท: ผู้ใช้ค้นหาข้อมูล / ผู้ดูแลข้อมูลบุคลากร
- Flow: ค้นหา → ดูข้อมูล → (ผู้ดูแล) แก้ไข/อัปเดต
1. ค้นหาบุคลากรที่ต้องการพบได้ง่าย (R)
2. ข้อมูลติดต่อ/สังกัด/ตำแหน่งเป็นปัจจุบัน (R)
3. ข้อมูลบุคลากรที่ไม่ถูกต้อง ท่านพบบ่อยเพียงใด (S: ไม่เคย / นาน ๆ ครั้ง / บางครั้ง / บ่อย)
4. (ผู้ดูแล) อัปเดตข้อมูลบุคลากรได้สะดวก (R)

### SYS002 ระบบลาออนไลน์  · has_tracking: ใช่
- บทบาท: ผู้ยื่นใบลา / ผู้อนุมัติ (หัวหน้า) / เจ้าหน้าที่ธุรการ-บุคคล
- Flow: ยื่นใบลา → ผู้บังคับบัญชาพิจารณา → อนุมัติ/ไม่อนุมัติ → บันทึกวันลา
1. ตรวจสอบยอดวันลาคงเหลือได้ชัดเจน (R)
2. การยื่นใบลาผ่านระบบทำได้โดยไม่ต้องใช้เอกสารกระดาษเพิ่ม (Y)
3. (ผู้อนุมัติ) พิจารณาและอนุมัติใบลาได้สะดวก (R)
4. ระยะเวลาตั้งแต่ยื่นจนได้ผลอนุมัติโดยทั่วไป (S: ภายในวันเดียว / 1–2 วัน / 3–5 วัน / มากกว่า 5 วัน)

### SYS003 ลงเวลาปฏิบัติงาน  · has_tracking: ไม่
- บทบาท: ผู้ลงเวลา / ผู้ตรวจสอบเวลา (หัวหน้า-ธุรการ)
- Flow: ลงเวลาเข้า → ลงเวลาออก → ตรวจสอบ/แก้ไขรายการผิดปกติ
1. การลงเวลาเข้า-ออกทำได้รวดเร็วและสะดวก (R)
2. เวลาที่บันทึกในระบบถูกต้องตรงตามจริง (R)
3. เคยลงเวลาไม่สำเร็จหรือต้องแจ้งแก้ไขภายหลัง ในรอบ 3 เดือนที่ผ่านมากี่ครั้ง (N)
4. ช่องทางลงเวลาที่ท่านใช้ (C: คอมพิวเตอร์ / มือถือ / เครื่องสแกน / อื่น ๆ)

### SYS007 ภาระงานสายวิชาการ  · has_tracking: ใช่
- บทบาท: อาจารย์ผู้กรอกภาระงาน / ผู้ตรวจสอบ (หัวหน้าสาขา-ผู้บริหาร)
- Flow: กรอกภาระงาน → ส่งตรวจสอบ → รับรอง → สรุปรายงาน
1. การกรอกภาระงานแยกตามหมวด (สอน/วิจัย/บริการวิชาการ ฯลฯ) ทำได้ชัดเจน (R)
2. ระบบคำนวณภาระงานให้ถูกต้องตามเกณฑ์ (R)
3. ระบบช่วยลดเวลาในการรวบรวมภาระงานเมื่อเทียบกับวิธีเดิม (R)
4. อุปสรรคสำคัญในการกรอกภาระงาน (L)

### SYS008 ภาระงานสายสนับสนุน  · has_tracking: ใช่
- บทบาท: บุคลากรสายสนับสนุนผู้กรอก / ผู้ตรวจสอบ-หัวหน้างาน
- Flow: กรอกภาระงาน → หัวหน้ารับรอง → สรุป
1. หมวดภาระงานครอบคลุมลักษณะงานของท่าน (R)
2. การกรอกและแก้ไขภาระงานทำได้สะดวก (R)
3. (หัวหน้า) ตรวจสอบและรับรองภาระงานของผู้ใต้บังคับบัญชาได้สะดวก (R)

## กลุ่มงานวิจัยและวิชาการ

### SYS004 ฐานข้อมูลงานวิจัย  · has_tracking: ไม่
- บทบาท: ผู้ค้นหา/ใช้ข้อมูล / ผู้บันทึกข้อมูลงานวิจัย
- Flow: ค้นหา → ดูรายละเอียด → (ผู้บันทึก) เพิ่ม/แก้ไขผลงาน
1. ค้นหางานวิจัยด้วยเงื่อนไขที่ต้องการได้ตรงประเด็น (R)
2. ข้อมูลผลงานวิจัยครบถ้วนเพียงพอต่อการใช้งาน (R)
3. วัตถุประสงค์หลักที่ท่านใช้ระบบ (C: ค้นหาอ้างอิง / รายงานผลงาน / ประกอบการขอตำแหน่ง / อื่น ๆ)
4. (ผู้บันทึก) เพิ่มผลงานใหม่ได้สะดวก (R)

### SYS005 คุณสมบัติอาจารย์ผู้รับผิดชอบหลักสูตร  · has_tracking: ไม่
- บทบาท: ผู้ตรวจสอบคุณสมบัติ (ผู้รับผิดชอบหลักสูตร/งานประกันคุณภาพ) / ผู้ดูแลข้อมูล
- Flow: เลือกหลักสูตร → ตรวจคุณสมบัติตามเกณฑ์ → สรุปผล
1. ระบบแสดงผลการตรวจคุณสมบัติตามเกณฑ์ได้ชัดเจน (R)
2. เกณฑ์/เงื่อนไขในระบบเป็นปัจจุบันตามประกาศ (R)
3. ระบบช่วยลดเวลาในการตรวจสอบคุณสมบัติเมื่อเทียบกับวิธีเดิม (R)

### SYS006 AHS KM Hub  · has_tracking: ไม่
- บทบาท: ผู้อ่าน/ผู้ใช้ความรู้ / ผู้เผยแพร่ความรู้
- Flow: ค้นหา/เรียกดู → อ่าน-ดาวน์โหลด → (ผู้เผยแพร่) เพิ่มองค์ความรู้
1. หาองค์ความรู้ที่ต้องการพบได้ง่าย (R)
2. เนื้อหามีประโยชน์และนำไปใช้ในงานได้จริง (R)
3. ความถี่ที่ท่านเข้ามาใช้ความรู้ในระบบ (S)
4. หัวข้อความรู้ที่อยากให้เพิ่ม (L)

## กลุ่มแผน งบประมาณ และการเงิน

### SYS009 แผนปฏิบัติการประจำปี  · has_tracking: ใช่
- บทบาท: ผู้จัดทำแผน/โครงการ / ผู้พิจารณา-ผู้บริหาร
- Flow: จัดทำโครงการ → ส่งพิจารณา → อนุมัติ → ติดตามผล
1. การบันทึกโครงการลงแผนทำได้สะดวกและเข้าใจง่าย (R)
2. การติดตามความก้าวหน้าของโครงการทำได้ชัดเจน (R)
3. (ผู้บริหาร) ดูภาพรวมแผนและโครงการได้เพียงพอต่อการตัดสินใจ (R)
4. เคยต้องกรอกข้อมูลโครงการซ้ำในหลายที่หรือไม่ (Y)

### SYS010 ระบบ KPI / แผนกลยุทธ์  · has_tracking: ใช่
- บทบาท: ผู้รายงานผล KPI / ผู้ตรวจสอบ-ผู้บริหาร
- Flow: กำหนด KPI → รายงานผลรายรอบ → ตรวจสอบ → สรุปเทียบเป้าหมาย
1. การรายงานผล KPI ในแต่ละรอบทำได้สะดวก (R)
2. ระบบแสดงผลเทียบเป้าหมายได้ชัดเจน (R)
3. ข้อมูล KPI ที่แสดงสอดคล้องกับที่ท่านรายงาน (Y)
4. (ผู้บริหาร) รายงานสรุปช่วยการตัดสินใจเชิงกลยุทธ์ได้ (R)

### SYS013 ระบบเสนอของบอิเล็กทรอนิกส์  · has_tracking: ใช่
- บทบาท: ผู้เสนอของบ / ผู้พิจารณา-อนุมัติ / เจ้าหน้าที่การเงิน-พัสดุ
- Flow: เสนอคำของบ → พิจารณา → อนุมัติ/ปรับลด → แจ้งผล
1. การกรอกคำของบทำได้ชัดเจน ไม่ซับซ้อน (R)
2. แนบเอกสารประกอบคำของบได้สะดวก (R)
3. ทราบสถานะคำของบโดยไม่ต้องสอบถามนอกระบบ (Y)
4. (ผู้พิจารณา) เปรียบเทียบและพิจารณาคำของบหลายรายการได้สะดวก (R)

### SYS020 ระบบลูกหนี้เงินยืม  · has_tracking: ใช่
- บทบาท: ผู้ยืมเงิน / เจ้าหน้าที่การเงิน
- Flow: ขอยืม → อนุมัติ → เบิกจ่าย → ส่งใช้/เคลียร์หนี้
1. ตรวจสอบยอดและสถานะเงินยืมของตนเองได้ชัดเจน (R)
2. การแจ้งเตือนกำหนดส่งใช้เงินยืมเหมาะสม (R)
3. (การเงิน) บันทึกรับคืน/ปิดลูกหนี้ได้ถูกต้องและสะดวก (R)
4. เคยพบยอดไม่ตรงกับเอกสารหรือไม่ (S: ไม่เคย / นาน ๆ ครั้ง / บางครั้ง / บ่อย)

### SYS021 ระบบ AHS e-donation  · has_tracking: ใช่
- บทบาท: ผู้บริจาค-ผู้ยื่นขอรับบริจาค / เจ้าหน้าที่ดูแลการรับบริจาค / ผู้บริหาร
- Flow: บันทึกรายการบริจาค → ตรวจสอบ → ออกเอกสาร/หลักฐาน → สรุป
1. การบันทึกรายการบริจาคทำได้สะดวก (R)
2. ได้รับหลักฐานการรับบริจาคครบถ้วนและทันเวลา (R)
3. ข้อมูลยอดบริจาคในรายงานถูกต้องตรงกับบันทึก (R)
4. (ผู้บริหาร) รายงานสรุปยอดบริจาคช่วยติดตามผลได้ (R)

## กลุ่มเอกสารและงานสารบรรณ

### SYS011 ระบบรับส่งหนังสือ  · has_tracking: ใช่
- บทบาท: ผู้ส่ง-ผู้รับหนังสือ / เจ้าหน้าที่สารบรรณ / ผู้บริหาร (ลงนาม-สั่งการ)
- Flow: ลงรับ/ส่ง → ส่งต่อผู้เกี่ยวข้อง → ดำเนินการ → เก็บเข้าแฟ้ม
1. ค้นหาและเรียกดูหนังสือย้อนหลังได้ง่าย (R)
2. ติดตามว่าหนังสืออยู่ที่ใครหรือดำเนินการถึงขั้นใดได้ชัดเจน (R)
3. ระบบช่วยลดการใช้กระดาษและการเดินส่งเอกสาร (R)
4. หนังสือที่ส่งผ่านระบบถึงผู้รับครบถ้วนหรือไม่ (S: ครบทุกครั้ง / เกือบทุกครั้ง / บางครั้งไม่ครบ)

### SYS012 กรรมการภายในต่างๆ  · has_tracking: ไม่
- บทบาท: ผู้ค้นหา/ตรวจสอบรายชื่อ / ผู้ดูแลข้อมูลคำสั่ง-กรรมการ
- Flow: ค้นหาคณะกรรมการ → ดูรายละเอียดคำสั่ง → (ผู้ดูแล) อัปเดต
1. ตรวจสอบว่าตนเองหรือผู้อื่นอยู่ในคณะกรรมการใดได้ง่าย (R)
2. ข้อมูลคำสั่งและรายชื่อกรรมการเป็นปัจจุบัน (R)
3. (ผู้ดูแล) เพิ่ม/ปรับเปลี่ยนรายชื่อกรรมการได้สะดวก (R)

### SYS014 AHS eForm  · has_tracking: ใช่
- บทบาท: ผู้กรอกแบบฟอร์ม / ผู้พิจารณา-เจ้าหน้าที่ผู้รับเรื่อง
- Flow: เลือกแบบฟอร์ม → กรอกและส่ง → พิจารณา → แจ้งผล
1. แบบฟอร์มที่ต้องการมีครบและค้นหาได้ง่าย (R)
2. การกรอกและส่งแบบฟอร์มออนไลน์ใช้เวลาน้อยกว่าวิธีเดิม (R)
3. ท่านเคยต้องกรอกแบบฟอร์มซ้ำหรือส่งใหม่เพราะระบบขัดข้อง/ข้อมูลหายหรือไม่ (Y)
4. แบบฟอร์มที่อยากให้เพิ่มเป็นออนไลน์ (L)

### SYS015 ดาวน์โหลดแบบฟอร์ม  · has_tracking: ไม่
- บทบาท: ผู้ดาวน์โหลดแบบฟอร์ม / ผู้ดูแลคลังแบบฟอร์ม
- Flow: ค้นหาแบบฟอร์ม → ดาวน์โหลด → (ผู้ดูแล) อัปโหลด/อัปเดต
1. หาแบบฟอร์มที่ต้องการพบได้เร็ว (R)
2. ไฟล์แบบฟอร์มเป็นฉบับล่าสุดและเปิดใช้งานได้ปกติ (R)
3. เคยดาวน์โหลดแล้วพบแบบฟอร์มล้าสมัยหรือเปิดไม่ได้หรือไม่ (S: ไม่เคย / นาน ๆ ครั้ง / บางครั้ง / บ่อย)

## กลุ่มอาคาร สถานที่ และทรัพย์สิน (ใกล้เคียงระบบแจ้งซ่อม)

### SYS016 ระบบบริหารจัดการอาคารและห้อง  · has_tracking: ใช่
- บทบาท: ผู้จองห้อง/ใช้ห้อง / เจ้าหน้าที่ดูแลอาคาร-ห้อง / ผู้บริหาร
- Flow: ตรวจสอบห้องว่าง → จอง → อนุมัติ → ใช้งาน/ปิดงาน
1. ตรวจสอบห้องว่างและตารางการใช้ห้องได้ชัดเจน (R)
2. การจองห้องทำได้สะดวกและไม่เกิดการจองซ้อน (R)
3. เคยเกิดปัญหาจองซ้อนหรือข้อมูลห้องไม่ตรงกับจริงหรือไม่ (Y)
4. (เจ้าหน้าที่) จัดการ/อนุมัติการใช้ห้องได้สะดวก (R)

### SYS017 ระบบบริหารจัดการครุภัณฑ์  · has_tracking: ใช่

## หมายเหตุสำหรับ Agent

- ข้อความข้างต้นเป็นตัวอย่างเริ่มต้น ปรับถ้อยคำให้เป็นภาษาผู้ใช้ทั่วไปและไม่ชี้นำได้ แต่ให้คงจำนวนและชนิดคำตอบโดยประมาณ ไม่ขยายเกินนี้
- ระบบ `has_tracking = ไม่` ให้ซ่อนหมวด T ทั้งหมดผ่านเงื่อนไขในข้อมูล (ไม่ใช่โค้ดเฉพาะระบบ)
- ทุกข้อ "(ผู้ดูแล)/(เจ้าหน้าที่)/(ผู้บริหาร)/(ผู้อนุมัติ)" แสดงเฉพาะบทบาทนั้น (`roles`)
- Mock ของระบบเหล่านี้ต้องตอบเฉพาะข้อที่ตรงกับบทบาทที่สุ่มได้ และ **ทุกระบบต้องมีคำตอบความพึงพอใจ** (S1–S4 + ข้อเฉพาะระบบ)
- ความพึงพอใจนำไปแสดงใน Dashboard แยกเป็นมุมมองของตัวเอง และใช้ร่วมกับตัวชี้วัดอื่นในสัญญาณ "ควรปรับปรุง" (AGENTS.md §6.1)
